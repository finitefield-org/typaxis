# Securityとresource limits

全limitを`ResourceLimits`、EffectiveConfig Schema、CLI overrideで同期する。既存のparser/include/text/font/image/fragment/pass/page/spool/object/output limitsに加え、`max_ast_nesting_depth`、`max_uri_bytes`、`max_line_reshape_passes`、`max_page_break_lookback`、`max_footnote_reflows_per_page`、`max_column_balance_candidates`、`max_float_queue`、`max_float_carry_pages`、`max_cids_per_font`をprofile 1.0の必須positive fieldにする。`max_source_bytes`は1 source、`max_input_bytes`はentry sourceと全includeの合計、`max_text_buffer_bytes`は1 buffer、`max_text_bytes`は全buffer合計へ適用する。`max_ast_nodes`と`max_style_rules`は1 ParsedPackage、`max_pages`と`max_fragments`は各materialized layout stateへ適用し、全passのwork量はさらに`max_layout_passes`との積で有界にする。`max_font_bytes`/`max_image_bytes`は各admission encoded input resource、`max_fonts`/`max_images`はunique declaration count、`max_resource_bytes`はadmit済みfont/image input bytesの合計へ適用する。これら3つをsubset/image encoder outputへ再適用しない。`max_spool_bytes`はowner phaseが同時に保持するpage spoolまたはverified plan payloadの合計、`max_pdf_objects`と`max_output_bytes`は1 build outputへ適用する。`max_source_bytes <= max_input_bytes`、`max_text_buffer_bytes <= max_text_bytes`、`max_shaping_context_bytes <= max_text_buffer_bytes`、`max_font_bytes <= max_resource_bytes`、`max_image_bytes <= max_resource_bytes`、`max_ast_nesting_depth <= 64`、`max_fonts <= 26^6 = 308,915,776`、`max_cids_per_font <= 65535`、`max_output_bytes <= 9,999,999,999`を要求する。six-uppercase-letter subset tag namespaceと同じ`max_fonts`上限により、全許可FontInstanceIdへcollision-free tagを割り当てられる。

`max_include_files`はentryを除く`max(sources.len - 1, 0)`で、entryはSourceId 0である。include depthはflattened packageから証明できないため、entryをdepth 0とする`ValidatedIncludeGraph`が最大edge depthを発行し、package constructorがそのreceiptを必須とする。`max_ast_nodes`のexact countはDocument typed semantic node数に、style declarationごとにdeclaration node 1とtyped value node 1を加えた値で、StyleRule本体は数えず`max_style_rules`側で数える。`max_ast_nesting_depth`はDocument root=1からtyped child edgeごとに増える最大depthと、root StyleRule=1から`extends` edgeごとに増える最大inheritance depthの大きい方である。上限値そのものをprofile maximum 64以下とし、exact maxは許可、max+1はrecursive validator、node index、fingerprint、cascadeへ入る前の反復precheckで拒否する。Schema validatorもこのsemantic precheckを先行し、reject対象の深いrecursive `$ref`へ入らない。`max_text_buffer_bytes`はparsed各bufferと各layout stateのGeneratedTextStore各bufferへ、`max_text_bytes`はparsed全buffer合計に当該stateの完全overlay合計を加えた値へstateごとに適用する。全stateのoverlayを一括加算しない。`max_shaping_context_bytes`は1 `ShapeRequest`のmain text、pre-context、post-contextのUTF-8 bytesをchecked加算した合計に適用する。`max_spool_bytes`は各owner phaseが同時保持するpage spool payloadまたはverified final-plan payloadの実測値であり、全phaseの総和や最終PDF output bytesへ代用して比較しない。ADR-0036のnon-current JPEG sanitizerだけはsourceとAPP0除去後streamが同時にliveとなるchecked合計を同limitへ一度chargeし、source admissionの`max_image_bytes`をtransform outputへ再適用しない。

layoutは`max_pages`、`max_fragments`、`max_layout_passes`に加え、lookback、footnote reflow、column candidate、float queue/carryを`PaginationWorkBudget`/`FragmentWorkBudget`、line reshapeを`LineLayoutBudget`としてrequestへ渡す。owner counterがmax+1回目のworkとallocationの前にconsumeを拒否し、外部Fragmenter/Paginatorが一部limitを受け取らない経路を許さない。PDF backendも`max_pdf_objects`をobject ID割当前、`max_output_bytes`を次のbyte write前にconsumeする。dense object allocatorはnext stateをObjectIdより広い整数で保持し、`max_pdf_objects = 4,294,967,295`の最後のvalid ObjectId発行後のsentinelを表現できる。exact maxは成功可能で、max+1 allocationは拒否する。

すべての`max_*`は許可最大値であり、count/size == maxは成功できる。max+1個目・byte・passをread、allocate、enqueue、evaluate、writeする前にchecked arithmeticで検出し、categoryに対応する安定diagnostic codeを返す。limit判定のために上限を超えるallocationを先に行わない。

include/font/imageのpackage内pathは`PortablePath`としてproject/admitted root内で解決する。config `resource_roots`は`ConfigResourceRoot`で、`ProjectRoot`だけをwire `"."`、その他を`Relative(PortablePath)`として表す。config rootsと`allowed_uri_schemes`はset意味なのでuniqueかつwire stringのUTF-8 byte昇順のcanonical arrayにする。admitted rootsは各ConfigResourceRoot variantをproject rootから解決したdirectoryとexplicit CLI host rootsを個別にcanonicalize/handle化した集合である。CLIで受けるhost INPUT/OUTPUT/config/resource-root/font pathはplatform-native `HostPath`として各host execution contextへ置き、absolute path、backslash、drive prefixを`PortablePath`規則だけを理由に拒否しない。resource declarationの`PortablePath`を全root相対にlookupし、contained existing regular-file candidateが0件ならnot-found、1件ならadmit、2件以上ならbytesが同じでもambiguous-path errorとし、明示順の先頭fileを黙って選ばない。admission後のcanonical artifact、EffectiveConfig、trace、manifestにはhost absolute pathを保存しない。URL fetchは初期版禁止。可能なplatformではdirectory handle相対openでTOCTOUを減らす。

font/image parserはuntrusted。unsafeは禁止し、external decoder結果もdimensionsとcanonical decoded buffer bytesを再検査する。PNG packed scanline量をdecoded allocation limitへ代用せず、合法IHDR組合せからalpha-capable expanded channel/sample幅をchecked計算する。`tRNS`を取り得るgrayscaleはGA、truecolorはRGBA、paletteはRGBA8を常にreserveし、chunk走査前でもallocationを過小計上しない。ADR-0036のnon-current JPEG targetはcanonical Gray8/RGB8量に加え、exact-pinned decoderで同時にliveとなるpadded component planes、MCU-row coefficients、output、upsample rowsのchecked peakも同じ`max_decoded_image_bytes`以内であることをexternal allocation前に要求する。TrueType profileはsfnt/TTC face signature、table bounds/uniqueness、unitsPerEm 16..=16384を検証し、CFFをFontFile2 planへ流さない。ADR-0036のCFF1 targetは別のFontFile3/CIDFontType0 planとprivate table/glyph/subroutine/operation/outline/subset limitsを使い、current configへ早期追加しない。resource admissionはcaller-supplied `exact_length`、任意`Read`、raw root path listをtrusted inputにしない。同一HostAdmissionContextから発行されたsealed `AdmittedRootSet`と、contained regular-file opener/stat ownerがそのroot set、same no-follow open handle、logical ID、観測lengthへbindしたopaque source receiptだけを受理する。root aliasはroot-set発行前、multi-root candidateはsource receipt発行前に拒否する。そのlengthをresource/aggregate budgetへreserveした後にexact bytesを読み、limit判定用のmax+1 byteは読まず、read後にsame-handle length不変を再確認する。pending bytes/metadata receiptはbudgetをconsumeしたresolver sessionにもbindし、別limitsのresolverへ移してledgerを発行できない。content mutationを防ぐimmutable snapshot/lockとopened-handle identityを証明できなければfail closedにする。URI-valued syntaxはsyntax境界でschemeをASCII lowercaseへ正規化し、allowed scheme、control/whitespace/NUL不在、raw UTF-8 lengthの`max_uri_bytes`上限を検査して`SafeUri`にする。PDF name/string/XML/URIは専用encoder/validatorだけを通す。

untrusted PDF direct arrays/dictionariesとPages hierarchyはそれぞれdepth 64をinclusive maximumとし、max+1 nestingをiterative walkで拒否する。indirect bodyのroot `PdfValue`、stream dictionary、root `/Pages`をdepth 1と数え、child container/valueまたはpage-tree childごとに1増やす。これはDocumentの`max_ast_nesting_depth`とは別のPDF profile固定値であり、reject payloadのdropもrecursive child traversalを使わない。
