# Table、footnote、column、float

初期tableはfixed/fraction column、cell paragraph、row fragmentation、repeated header。tableは1列以上を持ち、fixed widthとfraction weightは正でなければならない。head、bodyの順にrowを処理し、各cellをsource orderで既存rowspanに占有されていない最左columnへ置いてspan rectangleを確定する。spanは1以上でgrid内に収まり、互いに重複せず、各rowの全columnをちょうど一度coverしなければならない。rowspanはhead/body境界を跨がない。header rowは先頭から連続し、headerだけでframeに収まらない場合はL5xxx errorとする。column widthはtable開始時に確定し、ページごとに変えない。oversized rowはcell内fragmentation、進捗不能ならoverflow diagnostic。

footnoteは本文仮配置、参照収集、footnote測定、reserved height更新、本文再fragmentを行う。最初の本文fragmentはreflow回数に数えず、reserved height更新後に本文を再fragmentするたび1回と数える。split policyは`forbid`、`allow`、`force_if_oversized`のいずれかで、1 page/stateあたりの再flowは`ResourceLimits.max_footnote_reflows_per_page`回まで許可する。max回目は実行でき、max+1回目を開始する前にG6xxx errorとして、そのpage stateをmaterializeしない。

footnote assignment closureはpass全体のunionではなく、各materialized stateごとにDocumentで参照されたFootnoteId集合と一致させる。split continuationでは同じFootnoteIdが複数pageに現れてよいが、同一page内のduplicateは拒否する。各pageのID arrayはFootnoteId UTF-8 byte順にする。

FootnoteDefinitionのgenerated markerはdefinition nodeをsite ownerとして保持し、definition内typed preorderで最初のtext-producing `Paragraph`または`Heading`をstyle ownerとする。該当blockがなければshaping receiptを発行しない。本文中のFootnoteReference markerは別siteであり、そのreferenceを含むnearest styleable blockをstyle ownerにする。footnote subflow materializationが未実装のphaseではdefinition markerを推測値でshapingせずfail closedにする。

ADR-0030の`footnote-1`はcontract 1.2上の固定policyとして、marker番号をFootnoteId UTF-8 byte順definition catalogの1-based ordinal、page assignment/paintをselected first-reference順、splitを`allow`へ固定する。最初のbody evaluationはreflowへ数えず、body fingerprint、ordered footnote set、全continuation、exact reservationの完全tupleが連続2 evaluationで一致した場合だけconvergedとする。`max_footnote_reflows_per_page`回目のreflowは実行でき、不安定ならmax+1開始前に`G6002`で停止してpage stateをmaterializeしない。continuationは専用FootnoteFlowId carryでbody cursorから分離し、MI3-07でこのreceipt/paint/PDF closureをpublic profileとして公開した。

ADR-0031はadvanced paginationをcurrent contract 1.3のpublic `header-footer-1`、`columns-1`、`float-1`へ分割した。MI3-12は三つを通常pipeline、conditional artifact closure、`m3-all.json`とともに一括公開した。`columns-1`の最終nonempty pageだけが`ResourceLimits.max_column_balance_candidates`個までstrictly increasingなcanonical targetを評価し、count == maxでの成功を許可、candidate fingerprintのoscillationまたはmax+1開始前に`G6003`で停止する。`float-1`はbalanceを拒否し、direct-body Figureをhere/top/bottom/next_pageの有限順序でFIFO評価する。queue長を`ResourceLimits.max_float_queue`、同一floatのpage carryを`ResourceLimits.max_float_carry_pages`で制限し、初期anchor pageはcarry 0、未配置のpage-boundary crossingを1と数える。queue/carryのcount == maxは許可し、max+1 enqueue/crossing前に`G6004`で停止する。候補のdrop、bypass、順序変更、block fallback、unbounded carryを行わない。
