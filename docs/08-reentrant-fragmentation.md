# Re-entrant fragmentation

pagination前に固定heightのfragment列を作らない。`Fragmenter`は毎回、frame、page context、reserved footnote height、`FlowPosition`、`LayoutEpoch`を受ける。

結果はplaced fragments、`Continuation`、discovered footnotes、anchorsを返す。anchor discoveryは`ValidatedDocumentNodeIndex`由来の完全な`AnchorId -> NodeId` registryに対してIDとownerの組を照合し、pagination permitがpage index、frame kind、column index、frame-local pointと結合した`PlacedAnchor`を発行する。unknown ID、wrong owner、同一pass内のduplicate ID、frame外pointを拒否し、選択されたmaterialized stateまでこの集合を保持する。`Continuation`は`Exhausted`または`More(FlowPosition)`で、`FlowPosition`はepochと`(global_flow_ordinal, owner, block_child_path, owner_local_boundary)`を持つglobal structured positionである。`global_flow_ordinal`はFlowTree構築時の0-based preorder、`block_child_path`は各container内の0-based child-index列、`owner_local_boundary`はowner型ごとのvalidated boundary indexで、opaque hashを順序componentにしない。epochは等値比較だけに使い、残るtupleを各componentのcanonical orderで辞書式比較する。

`LayoutEpoch`はdocument、style/page-master、`AdmittedResources` identity/metadata、resolved generated-reference inputの各typed fingerprintを持つ。`PackageEpochIdentity`は`ValidatedParsedPackage`からだけdocument/style fingerprintを発行し、下位`typaxis-layout-contract`の`LayoutEpoch` owner constructorはそのidentity、`AdmittedResourceLedger`がfingerprintしたidentity、完全な`GeneratedTextStore`がreference fingerprintしたidentityの組だけを受ける。`typaxis-layout`はこの型をre-exportするだけである。caller-supplied digest bytesや未検証ParsedPackageからtrusted epochを発行しない。admitted resource fingerprintはlogical ID順のsource hash、face index/dimensions、shapingに影響するmetadataを含むが、Display後に確定するusage、subset、CID、image encoding、`FrozenPdfResourcePlans`を含めない。したがってlate finalizationからlayoutへの循環依存を作らない。いずれかが異なるFlowPositionを流用できず、resolved reference fingerprintにはdocs/05の`GeneratedBufferKey`、provenance range、正確なUTF-8 bytesを含める。

epoch fingerprintはすべてrecord中の`algorithm`を含むRFC 8785 JCS UTF-8 bytesへSHA-256を適用する。Document recordは`algorithm = typaxis.document-state.sha256/1`と`contract, coordinate_unit, document, resources, sources, text_buffers`を持つ。`resources`はFontFaceId/ImageResourceId宣言順の完全なResourceCatalogで、fontの`font_face_id, family, uri, face_index, expected_sha256`とimageの`image_id, uri, expected_sha256`を含む。これにより本文が同じでもresource declarationが違うpackageは同じDocumentFingerprintを共有しない。Style recordは`algorithm = typaxis.style-state.sha256/1`と`page_masters, style_sheet`だけを持つ。Admitted recordは`algorithm = typaxis.admitted-resources.jcs-sha256/1`、fontをFontFaceId順の`font_face_id, family, face_index, sha256, units_per_em, glyph_count`、imageをImageResourceId順の`image_id, sha256, pixel_width, pixel_height, decoded_bytes`として持つ。admitted recordからresource URI、encoded byte length、expected hash、usage/subset factsを除外しても、宣言自体はDocument recordに残る。fontの`units_per_em`はProfile 1.0 TrueType有効範囲16..16384、`glyph_count`とimage dimensionsは1..4294967295のactual admitted metadataである。Reference recordは`algorithm = typaxis.reference-state.jcs-sha256/1`とcanonical `resolved_generated_text`を持ち、algorithm無しの同形JSONを同じdomainとしてhashしない。

`CanonicalFlowIrBuilder`は`ValidatedDocumentNodeIndex`のtyped child pathからeligible owner/kindとlocal boundaryを導出し、完全なFlowTreeを発行する唯一のownerである。caller-provided Vec順、任意path、opaque boundary hashをposition identityに使わない。nonblank flowではindex 0をDocument rootの`DocumentStart (owner=0, path=[], local=0)`、index 1..len-2をpaintable boundaryの`(owner, block_child_path, owner_local_boundary)`順、last indexを明示的な`End (owner=0, path=[], local=1)` sentinelとする。したがってtuple sortと同一owner/path内のlocal dense検査は中間のpaintable boundariesだけに適用し、末尾Endを先頭DocumentStartと隣接させるために並べ替えない。blank flowだけはsole DocumentStartがterminalを兼ね、別End recordを足さない。cursor、fragment start/end、continuationは同じFlowTreeのexact memberだけを持ち、nonblankの`Exhausted`は末尾End、blankの`Exhausted`はsole DocumentStartを指す。syntax validationはListを1件以上のitem、Tableを1行以上に限定するため、非空container ASTがFlowTree上だけemptyとなってblank-document publication規則と矛盾する入力を受理しない。

同じrequestから同じresultを返す決定性が必要。`More(next)`は同じepochのglobal canonical structured orderでrequest positionより厳密に大きく、かつterminal以外でなければならず、owner境界を跨ぐ前進を許す。非前進はfragmentの有無やoccupied block sizeに関係なくzero-progress errorであり、opaque fingerprintの不一致だけを進捗として認めない。terminalだけを`Exhausted`にできる。
