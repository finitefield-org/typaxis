# ADR-0039: Book-2 semantic vocabulary and version-bound carrier

## Status

Accepted for implementation on 2026-09-08 as part of
[the VMB full-book compatibility work](../docs/28-vmb-book-production-compatibility.md).
This is a non-current contract-1.5 decision. It does not publish a profile,
change any frozen contract, or establish full-book/PDF support.

## Context

The actual fractions book contains 260 solutions and 328 admonition containers:
122 examples, 92 notes, 62 common errors, 32 warnings, 11 counterexamples,
6 formalization notes and 3 remarks. Contract 1.4 has only result, proof and
exercise containers. ADR-0032 expressly forbids using a class or flattened
paragraphs in place of a typed grouping boundary. A solution is not silently
converted to a proof, and an example is not silently converted to a result.

Section 9.1 of the compatibility design already reserves contract 1.5 and
production-book-2 for versioned CFF admission and the next capability registry.
The same complete successor publication must include the full-book semantic
vocabulary. The unchanged-Harano, complete exporter, original full-book,
managed-host, independent PDF and human acceptance gates still apply.

## Decision

The successor semantic container keeps the existing closed record shape:
`kind`, `node_id`, `span`, `classes`, `semantic_kind`, nullable `anchor_id`,
ordered nonempty `blocks`, and optional `language`. Contract 1.5 accepts exactly
these semantic kinds:

```
result
proof
exercise
solution
example
counterexample
remark
note
warning
common_error
formalization_note
quote
```

These are closed typed alternatives. VMB `commonError` and `formalizationNote`
map explicitly to `common_error` and `formalization_note`; the original VMB
kind and origin remain producer metadata. An arbitrary `admonition`, `other`,
custom role, or extension string is not accepted. Labels, titles, attribution,
verification and child contents are ordinary explicitly sourced children,
never inferred or generated by the container itself.

Every container retains its actual kind, ordered children, anchor, language,
source span and grouping owner in document body, nested containers, list items,
table cells, figure/vector captions and footnote definitions. The separate
header/footer grammar remains paragraph/heading only. Dense preorder IDs,
parent/child span containment, recursive emptiness, depth/work limits, selected
fragment coverage, page splitting and source/provenance validation have the
same obligations as the existing container. They must be validated in the
successor syntax/profile/layout owners; decoding the carrier is not that proof.

The planned PDF role for `quote` is standard `BlockQuote`; the other container
kinds are standard `Sect`, while their exact kind remains in typed semantic and
structure evidence. No class, rendered label or page coordinate may select a
kind or role. Visible box decoration remains explicit style, not implicit paint.
The closed kind set is carried into versioned style/flow/structure identities,
not cast into a 1.4 profile receipt or one of its three kinds.

## Shared implementation and isolation

The recursive carrier shape and its bounded JSON, duplicate-member, declared
resource, native/precomposed math, language, metadata, canonicalization and AST
charge checks may be shared. The semantic-kind type selects the exact contract;
a sealed trait permits only crate-owned closed enums. The existing 1.4 API names
remain monomorphic aliases to the original three-kind type. A successor tree
cannot be passed as a 1.4 tree, and neither decoder retries under another version.
The internal temporary 1.3 carrier used to validate unchanged supporting fields
is not an exported document; the typed successor document retains every wrapper.

The non-current module is compiled only for tests or the explicit
`book-v2-staging` Cargo feature. Normal public decoder/encoder dispatch, current
contract, profile names, capabilities, help and schema aliases stay at 1.4.
The feature grants no renderer/PDF authority. It must be removed or absorbed
into the single complete publication change set, together with all other private
successor entry points, when section 9.1's gates are actually proved.

Description lists (30 in the original book), remaining teaching fields and
ordinary reference/renderer support remain necessary work in the unpublished
successor. This container decision does not call their existing rejection a
successful full-book export and does not reduce the original scope.

## Required evidence

- Every successor kind survives canonical decode/encode with original children,
  source spans, language, classes and anchors in every general recursive slot.
- Old three-kind DTOs and raw 1.4 decoder still reject every new kind; public
  dispatch/current contract still reject 1.5, including when the staging feature
  is compiled for tests.
- Duplicate, missing, null, unknown or extra members; recursively invalid child
  shape; empty containers; invalid math and supporting fields; page-region
  containers; mutated typed input; and over-budget inputs fail.
- Exact AST/resource/package budgets and canonical/hash identities are checked.
- Existing document-package, syntax and public production compatibility tests
  remain successful. Full successor layout/structure/PDF/CLI and full-book gates
  must be separately demonstrated before publication.
