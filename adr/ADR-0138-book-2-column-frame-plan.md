# ADR-0138: Book /2 の元マスターに結び付く段組ページ計画

- 状態: 実装（ページ計画。物理ページの選択・描画は継続）
- 日付: 2026-10-07
- 関連: [設計 §14.275](../docs/28-vmb-book-production-compatibility.md#14275-元マスターから段組の実幅と位置を計画する実装追補)

## 問題

Book /2 の本文ページ計画は一つの矩形だけを扱い、`column_layout` を拒否する。
既存の `columns-1` 実装は専用フローのため、Book /2 の元の表・脚注・名前付き
ページを持つフローへ、その選択結果をそのまま渡せない。段組を有効にするには、
元マスターに基づく実段幅と位置を、本文全幅と区別して保持する必要がある。

## 決定

`BookV2ColumnFramePlan` を単段の `BookV2PageFramePlan` と別の型にする。
元 source の同一性、first／parity／名前の選択と元 owner の名前要求を保持する。
名前の走査は本文・定義の全フローに共通とし、脚注内の要求も取り落とさない。
選択可能なページ数が一つ／二つの場合は、その上限内で到達する class だけを準備する。
未選択マスターの不正な段幅から、選択済みのページ計画を拒否しない。

段の順序は左から右、fill は元の `sequential` とする。本文幅から全 gap を差し引き、
段数で整数除算した幅を各段へ与え、端数を最後の段へ足す。元本文矩形の右端へ
厳密に閉じること、各段の正の幅、gap・座標の算術と JSON-safe な範囲を検査する。
段数・基本幅・端数を保持し、個々の矩形を定数時間で求める。65,535 段の宣言に対しても、
段数に比例する新しい配列は確保しない。

初期測定 envelope は到達する全 class の最大の実段幅・本文高を持つ。実段幅の差と
脚注幅の差から幅の再計算が必要かを判定する。元の本文全幅も別に保持する。
全ページの脚注矩形を段数で分割せず、元の独立した物理領域として保持する。
最終ページの `last_page` balance は元の要求として保持し、採択済み balance receipt
とは扱わない。柱・footer の元 source と矩形は引き続き元マスターに結び付く。

計画を単段の layout API へ渡す変換は提供しない。既存の単段ページ計画、private PDF
driver、PDF assembly の段組拒否は維持する。これにより、段数だけを受理して本文を
全幅へ描画することや、各段を別の物理ページとして公開することを防ぐ。

## 予算と検査

各到達 class の論理段 template 数を、構築前に caller の累積 record／work へ予約する。
名前の文字列と source の走査も既存の共通予算へ接続する。counted constructor は
成功・失敗の双方で、caller の履歴と受理済みの record／spool の prefix を返す。
拒否された予約は計上せず、再試行の work は返金しない。圧縮した template の検査を、
command 全体の allocation・capacity・一時領域の監査の代替にはしない。

元 package の literal 座標から first／parity／名前付きページ、最後の段の端数、
単段との混在、脚注領域と定義内の名前を検査する。最大段数、正の幅と算術の境界、
未到達マスター、page cap、別 source の拒否、work／record／spool の exact／1不足と
失敗 prefix を検査し、型の変換拒否を compile-fail で確認する。回帰のコマンドと
範囲は [進捗 §275](../docs/28-vmb-book-production-progress.md#book-2-column-frame-plan-design-14275)
へ記録する。

## 継続する作業

段ごとの元 cursor と再組版、同じ物理ページの全段・脚注の共通候補選択、改ページ・
keep・表の継続と反復 header、最後の物理ページの balance、PDF の実段配置と
独立検証を接続する。公開 Book /2 の gate、元全巻の単一 PDF、完全な command 予算、
管理ホスト・性能・著者／人手受入も継続する。本計画だけで段組 PDF の成功とはしない。
